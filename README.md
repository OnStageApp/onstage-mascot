# onstage-mascot

The OnStage mascot, one character for the web client and the mobile platform. OnStage is a service
planning platform for churches; the mascot shows up in welcome, empty, success, reminder and problem
states (never on billing, payment or paywall screens, grief or prayer requests, or Live Mode).

The mascot's real name is undecided. Working names live in one place, [`mascot.config.json`](mascot.config.json):
repo `onstage-mascot`, npm package `@onstage/mascot`, Dart package `onstage_mascot`, component `Buddy`.
To rename: `node tools/rename.mjs component=Pip npmName=@onstage/pip dartPackage=onstage_pip repo=onstage-pip`,
then `npm run build && npm test` (`tests/names.test.mjs` checks everything agrees).

## How sameness works

Sameness comes from data, not copied logic.

- **`spec/` is the only hand-edited source of truth** for what the mascot looks like and how it moves:
  shapes, palette, states and motion. Players read only `spec/`.
- Motion is **baked**: the animation engine and its smoothing rig run once, at bake time, and the
  result is stored as frames. No player implements springs or easing.
- Each platform has a small, dumb player that interpolates a frame of numbers and draws rects,
  ellipses, circles and paths, following [`docs/renderer-contract.md`](docs/renderer-contract.md).

## Layout

```
spec/                     the data (format 1, see spec/README.md)
  palette.json            colour tokens, light and dark
  states.json             85 states: scene, rest poses, motion
  motion/<id>.json        baked clips (generated by bake)
docs/renderer-contract.md the player algorithm, precise enough to port mechanically
tools/
  source/                 verbatim copies of the engine and the state generator (provenance in each header)
  motion/definitions.mjs  motion sources: what each clip does over time
  lib/                    rig, path normaliser, SVG subset parser, sampler, JSON writer
  bake.mjs                spec from sources; import-generator.mjs (one-off import of the 85 states)
  render-svg.mjs, render-png.mjs, contact-sheet.mjs, serve.mjs, rename.mjs
packages/web/             TypeScript player: renderFrameSvg, createPlayer, React <Buddy>
  src/spec-data.ts        generated from spec/ (do not edit)
  dist/                   built ESM + .d.ts (checked in, so a git dependency needs no build)
packages/flutter/         the Flutter player (next phase)
examples/playground.html  every state, live, from the package build
tests/                    node:test suites; parity/ harness for the Flutter port
reports/                  bake-report.json (tolerances, sizes), rest-parity/
```

## Commands

Needs Node 20+, Python 3 with Pillow and numpy, and `rsvg-convert` (`/opt/homebrew/bin/rsvg-convert`,
or set `RSVG_CONVERT`).

```sh
npm install
npm run bake            # bake spec/motion from tools/motion, write reports/bake-report.json, regenerate web data
npm run bake -- --import   # also re-import palette.json and states.json from the generator (overwrites hand edits)
npm run build           # web package: spec data module + tsc to packages/web/dist
npm test                # all tests (key list, rendering, round-trip, determinism, rest parity, package, names)
npm run preview         # then open http://localhost:5178/examples/playground.html
npm run contact-sheet   # out/contact-sheet.png; add -- --motion hello for a motion strip
npm run render-png -- hello --phase motion --frame 20 --size 480
npm run parity:web      # tests/parity/web/*.png + manifest.json for the Flutter comparison
```

After editing `spec/states.json` or `spec/palette.json` by hand: `npm run bake && npm run build && npm test`.
The test that re-imports the generator and expects an identical `states.json` will then fail on purpose;
delete it once spec/ has deliberately moved on from the generator.

## Using it in an app

**Web (Next 16, React 19).** Install from a git tag:

```json
"dependencies": { "@onstage/mascot": "github:OnStageApp/onstage-mascot#v0.1.0" }
```

```tsx
import { Buddy } from '@onstage/mascot/react';         // client component ('use client' inside)
import { renderFrameSvg } from '@onstage/mascot';      // pure, server-safe

<Buddy state="no-events" size={160} onDone={() => setShowCta(true)} />
```

`Buddy` props: `state`, `surface` (`light` | `dark`), `size`, `playOnMount`, `onDone`, `reducedMotion`
(undefined follows `prefers-reduced-motion`), `label`, `className`, `style`. It server-renders the
resting pose, plays the state's motion once, idles with random blinks, and pauses while the tab is
hidden. Framework-free: `createPlayer({ state, target })`. React is an optional peer dependency.

**Flutter.** Dart git dependency on the same tag:

```yaml
dependencies:
  onstage_mascot:
    git:
      url: git@github.com:OnStageApp/onstage-mascot.git
      ref: v0.1.0
      path: packages/flutter
```

The Flutter package embeds `spec/` as a generated Dart file (`lib/src/spec_data.g.dart`) and implements the same contract.

## Versioning

Releases are git tags (`vMAJOR.MINOR.PATCH`), shared by both packages. Both apps pin a tag, so they
can never drift apart. Release steps: `npm run bake && npm run build && npm test`, bump `version` in
`package.json` (and `pubspec.yaml`), commit including `packages/web/dist`, tag, push the tag.
After `npm run bake`, also run `dart run tool/gen_spec_data.dart` and `node packages/flutter/tool/web-trace.mjs`
(in `packages/flutter`) so the Flutter data and the blink trace match, then `packages/flutter/tool/parity.sh`.
A breaking change to `spec/` bumps its `format` and the major version.

## Where things came from

- Drawing of every state and prop: `claude-brain/design-work/mascot/v2/blue-app-states.js`, copied
  verbatim to `tools/source/blue-app-states.cjs`. The Figma component set `Mascot/Buddy App` was drawn
  from the same generator, so the keys and the rest frames match it (rest-pose parity test).
- Motion engine and rig: `claude-brain/design-work/mascot/buddy-anim/buddy-anim.js`, copied verbatim to
  `tools/source/buddy-anim.cjs`. `tools/lib/rig.mjs` extends its rig to the full pose and is tested
  against the original.
- Reference PNGs: `blue-app-states/png`, copied to `tests/fixtures/rest-reference`.
